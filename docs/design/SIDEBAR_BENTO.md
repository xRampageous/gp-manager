# Sidebar presentation

Current candidate: 1.0.0. The sidebar uses three pages: **Live, Ledger and Grinds**.

- **Live** shows current activity, Net, gains, supplies, losses, rate, a Net target
  and recent changes. Click the status gem to pause/resume; there is no separate
  Resume Tracking button.
- **Ledger** groups gains, costs, market, deaths and Review. A row opens its receipts;
  one Correct menu provides counted treatment, transfer/exclude, split and undo.
- **Grinds** owns named run lifecycle, saved setups and targets, completed runs,
  All time, CSV export and profile backup/reset actions.

Free play is the durable owner outside a named Grind. All time is a projection,
not a second booking owner. Each receipt belongs to exactly one financial owner.
Stable session IDs retain identity through name changes.

Pages consume detached snapshots and accounting projections. Display filtering
cannot alter money. Unknown/partial coverage is shown honestly. Domain mutations
run through the client-thread boundary; Swing rendering runs on the EDT.

HUD+ shares activity and accounting presentation, fits an empty run to one row,
wraps money when narrow and explains filtered gains. Starting a different session,
even with the same name, clears the previous session's tray and moments.

Backups & recovery offers local backup, restoring a backup with a safety copy first,
copying the data-folder path, clearing old backups while keeping the newest, and
factory reset with Back up first.

Deterministic screenshots are generated by `panelPreview`. They illustrate model
fixtures and do not establish live-game acceptance; use
[the acceptance matrix](../LIVE_ACCEPTANCE_MATRIX.md) for that.
