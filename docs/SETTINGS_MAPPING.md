# Settings → runtime mapping (1.0)

> September 13 qualification: the shared eligibility contract is an architectural target. CSV detail/activity/PK and some retained/PK projections still use raw values. Blowpipe and Trident have offline Check-to-Check charge producers; charge-dialog reads, other charge families, utility-container producers and some live interfaces remain incomplete. See B03/B04, [charge accounting](design/CHARGE_ACCOUNTING.md) and the review checkpoint. Do not read the older universal-coverage wording below as completed verification.

Audit of the configuration interface against production callers. The RuneLite group remains `profitmanager`; the current configuration schema is **31**. Visible settings map to a runtime consumer for their intended surface; some appearance colours are surface-scoped (for example Legacy HUD title colour does not paint HUD+ or Compact). Hidden keys (`showOverlay`, `showLiveGpDrops`, `feedbackStyle`, `infoBoxTitleMode`, `defaultSessionName`, `defaultSessionMode`, `keepRewardTrayExpanded`, `autoResumeOnActivity`, `hudPlusMaxHeight`, legacy `gpDropFontStyle` / `gpDropOutline`) remain only for migration.

## Section taxonomy (display-related)

| Section | Surface | What belongs here |

Height always hugs tray content (Max height retired; Visible item rows caps cassette). |
| HUD+ - Item tray | HUD+ tray | Reward tray, Detail panel, Tray dwell, Loot coalesce (Ground Loot only), **Show banking flashes**, accumulation, Visible item rows |

| HUD - Custom rows | Legacy HUD Custom | Optional row toggles (Custom detail only) |
| HUD appearance - Shared | HUD+ shell + legacy HUD | Theme (background) + Custom colours for **legacy HUD Custom only** — not HUD+ text colours (see HUD+ - Colours) |

| Loot visibility | HUD+/HUD/Floating/Live/Ledger | Presentation filter, minimum displayed loot value, Ground Items colour reuse |
| Floating drops | Floating overlay | Preset, cost/uncertain visibility, floating minimum, hang time |
| Floating drops - Appearance | Floating overlay | FontType font, text background (None/Shadow/Outline), colours (@Alpha), spacing, alignment |
| Floating drops - Animation | Floating overlay | Vertical/horizontal float speed (px/s), cascade stagger, entry animation, motion direction/distance, fade, overlay priority |
| Floating drops - Custom preset | Floating Custom | Content/icon/combine controls when preset = Custom; icon size visible |

Width is **not** shared across modes: HUD+ Auto Resize hugs Trip Beacon **and** hover folio content up to the hard 320px cap each; with Auto Resize off, **Max width** fixes both shells. Height always hugs the cassette (expand/collapse with tray); **Visible item rows** caps row count. Legacy HUD has its own width; native Infobox sizing belongs to RuneLite.

### HUD+ sizing and Visible item rows

- **Auto Resize** (default on): Trip shell and Detail folio each hug measured content up to 320px; Max width is ignored.
- **Auto Resize off**: **Max width** (120–320, default 260) fixes Trip and folio width. Height still hugs content.
- **Max height** is retired (hidden). Tray height is bounded by Visible item rows + `+N more`.
- **Default session mode** is retired (hidden). New sessions always start as Auto; pick PK/Mixed when editing a custom session.
- Skilling/process trays: **Always Expanded** keeps confirmed gain/process receipts for the **session** across skill and activity changes (multi-skill cassette tag **Session**; Visible item rows + `+N more`). **Auto-collapse** stays **activity-scoped** (same skill may accumulate under activity-hold; switching skills replaces — Firemaking→Cooking does not Mixed-bleed under AC).
- **Total** is always session Net (soft pulse when Net changes). Tray loot sum never replaces Total (banking flashes do not move Total).
- **Show banking flashes** (default on): Deposit/Withdrew tray flashes; off silences them. Claimed ≠ banking.
- **AFK pause** default off so timer/GP/hr follow wall-clock; opt-in excludes AFK time from rates.
- **HUD+ text size** (Small / Normal / Large): scales Trip Beacon glyphs and item icon slots.
- **Show activity header** (default on): activity name, status gem, and elapsed timer. Off starts the shell at the metrics row.
- **Show metric labels** (default on): paints `GP/hr:` and `Total:` on the Trip Beacon hero.
- **Show item icons** (default on): item sprites on the tray and Detail folio. Off shows name + GP only.
- **Show tray tags** (default on): Chopped / Ground Loot / Mixed and similar left cassette labels. Off keeps the dwell/countdown when present.
- **HUD+ background opacity** is the only HUD+ alpha control. Custom background supplies RGB; its alpha is ignored on HUD+.
- **Status gem colours** (no separate pickers): AFK coral pulse; Paused/Recovery coral; Stopped/Hold/No session dim muted; Banking muted grey (neutral UI); Idle muted; **Busy** (coalesce, post-lock countdown, or activity-hold — including Pending Rewards) live-accent pulse and **beats Idle** while the cassette is open; first-use Waiting uses the neutral solid gem; generic live with an empty header and active named activity use live accent **solid**. When accent equals label grey (factory `#8B93A7`), live accent falls back to teal `#2EE6D6` so Active/Busy stay visible.
- **Visible item rows** (default 5) decides how many distinct cassette/folio rows paint and when `+N more` appears.
- **Idle ≠ Tray dwell ≠ AFK ≠ Loot coalesce**: Character Idle is presentation-only (releases activity-hold). Loot coalesce ticks stack same-NPC Ground Loot briefly, then Tray dwell folds the cassette. AFK pause (when enabled) excludes time from GP/hr.
- **Process skill switch (soft-stick)**: Lighting/cooking/Make-X questions/Tend-to/chat/XP that names a *different* process skill immediately clears conflicting process scenery soft-stick and NPC interaction titles so the header follows the live skill (`ProcessSkillSignals` table). Gather scenery (Willow tree / rocks) stays until Idle or retarget — not hard-cleared mid-chop. Tray sources stay isolated (Ground Loot ≠ Received ≠ Mixed ≠ Claimed); cross-skill replace does not Mixed-bleed. Open process-spend intent matches spend families only (e.g. Firemaking→logs). Action Progress is reference-only (no runtime dependency).
- **Factory reset before validating HUD+ builds**: lingering `profitmanager` keys can fake bugs. Prefer Manage data → Factory reset (or a clean profile) after installing a polish build, then reload the client.

`DedicatedHudRenderer` (the HUD+ renderer only) always reads these five keys, regardless of **Theme (HUD+ and HUD)** / `infoBoxTheme`. The legacy HUD keeps using the theme switch and, on `CUSTOM`, the `infoBoxCustom*` keys from **HUD appearance - Shared** — the two colour sets never mix.

| --- | --- | --- | --- |
| `hudPlusProfitColor` | HUD+ profit colour | `#5CFFB0` (mint) | GP/hr and Total text when that metric's own value is positive. |
| `hudPlusLossColor` | HUD+ loss colour | `#FF6B6B` (coral) | GP/hr and Total text when that metric's own value is negative. Coloured independently by each metric's own sign. |

| `hudPlusHeaderColor` | HUD+ header colour | `#E8ECF4` | Header row: activity/status name and elapsed time. |

## Contribution eligibility contract (accounting vs. presentation)

`accountingItemFilter` and `lootPresentationFilter` both read Ground Items rules through `LootPresentationFilterService`, but they answer two different questions and must never be confused:

| Setting | Answers | Backing type | Can it change revenue/costs/net? |
| --- | --- | --- | --- |
| `lootPresentationFilter` (Loot item visibility) | "What should reward trays, floating drops, Live item lists, Ledger item rows, and Insights item rows *show*?" | `LootPresentationFilterService.filterReward` / `isFlowVisible` / `highlightColorFor` | No — display-only, always. Hides gain rows; costs remain visible unless the separate accounting exclusion is active. |
| `accountingItemFilter` (Accounting item filter, advanced) | "Should this item's flow *count* toward revenue/costs/net at all?" | `com.gpmanager.grounditems.ContributionEligibility` (wraps `LootPresentationFilterService.isFlowIncluded`) | Yes — this is the only item-visibility setting allowed to. |

`GpManagerEngine#activeContributionEligibility()` returns a `ContributionEligibility` (or `null` for "count everything") for the filtered metric projections used by HUD/HUD+/Infobox/rate/target, the Ledger, and session history/Insights trend rows. In `CsvExporter`, diagnostics/headline metrics and comparison summaries accept eligibility, while detailed transactions, item flows, activities, PK projections and audit exports remain raw. That CSV split is a known B03 consistency gap; do not describe raw audit/detail exports as filtered accounting reports. No new display/export path may read `lootPresentationFilter` for anything other than presentation. See `com.gpmanager.grounditems.ContributionEligibility`'s class javadoc for the full contract, including how it stays correct against `ProfitSession`'s compacted historical totals (it is evaluated against the retained per-item breakdown, not against a flattened aggregate — so it never silently re-includes, or zeroes, a compacted item's historical contribution).
